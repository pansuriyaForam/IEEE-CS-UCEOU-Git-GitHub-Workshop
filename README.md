# Git & GitHub Workshop 🚀

### IEEE Computer Society — UCEOU

Welcome to the official repository for the Git & GitHub Workshop organized by the IEEE Computer Society, UCEOU.

This repository contains the workshop presentation, practice resources, and contribution guidelines to help participants move from using Git individually to collaborating with others and contributing to open source.

---
## 🎯 What You'll Learn

The workshop focuses on taking your Git knowledge beyond "add", "commit", and "push".

You will learn how to:

- 🍴 Fork a repository
- 📥 Clone a repository
- 🌿 Create and work with branches
- 🔀 Merge branches
- ⚔️ Understand and resolve merge conflicts
- 🚀 Push changes to GitHub
- 🔃 Create Pull Requests
- 👀 Understand code review
- 💬 Respond to review feedback
- 🌱 Understand the open-source contribution workflow

---

## 🔄 The Collaboration Workflow

The core workflow covered in this workshop is:

Fork
  ↓
Clone
  ↓
Create a Branch
  ↓
Make Changes
  ↓
Commit
  ↓
Push
  ↓
Pull Request
  ↓
Code Review
  ↓
Update Changes
  ↓
Merge

The goal is not just to learn commands, but to understand how developers collaborate on the same codebase.

## 🛠️ Prerequisites

You don't need to be an open-source expert to contribute.

You should have:

- Basic familiarity with Git
- A GitHub account
- Git installed on your computer
- A text editor or IDE
- Willingness to experiment and learn

If you attended Day 1, you already have the fundamentals needed to start with the Day 2 workflow.

---

## 🌱 Your First Contribution

You don't need to build a huge feature to contribute to open source.

You can start small.

Some examples of meaningful contributions:

- 📝 Fix a typo or documentation issue
- 📖 Improve an explanation
- 💡 Add a useful Git/GitHub example
- 🔗 Add a useful learning resource
- ❓ Add a beginner-friendly FAQ
- 🛠️ Improve existing documentation
- 📚 Add notes or examples that help future learners

Make your contribution meaningful rather than creating changes just for the sake of opening a Pull Request.

## 📌 Why This Repository Exists

Git becomes much more powerful when you stop using it only for your own projects.

Real software development involves:

- Multiple developers
- Multiple branches
- Code reviews
- Pull Requests
- Merge conflicts
- Discussions
- Open-source communities

This repository is designed to give you a small, practical environment to experience that workflow yourself.

«Don't just learn Git. Use Git to collaborate.»
